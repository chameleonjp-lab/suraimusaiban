# スライム3Dモデル確認

2026-10-23。原本は `src/scene/slime.ts` の手続き形状、シェーダー、決定的な待機ポーズです。添付JPEGを貼った平面ではなく、閉じた胴体、厚みのある頭頂の巻き、後方の二段の流れ、前面の曲面の目、3つの液滴で構成しました。口、神魔の付属物、回答や判決に反応する入力はありません。`createCourtroom()` は石・木の室内と裁判官・検察・弁護士の簡略3D人物を返します。

## 参照との比較

4枚のJPEGを実見し、正面・側面・背面と参照シートの特徴を確認しました。[参照とモデルを並べた画像](scene/reference-comparison.png)の左が参照、右が実際の3Dレンダーです。形状は低い部分が広い胴体、大きなS字の巻きと内向きの先端、後ろへ流れる裾、縦長の濃藍の目を維持しました。参照の手描きの複雑な内部模様は、控えめな流れの帯と2〜3段の陰影に整理しています。背景に溶けないよう青紫の縁を残し、艶を白い大きな反射にしています。目は下側に青い反射があります。

動画は `t=frame/15` の固定時刻150フレームをレンダーしてエンコードしたものです。実時間の速度測定には用いません。

5方向と24方向一覧を目視確認しました。背面に目は表示されず、側面では近い片目の縁だけが自然に見えます。胴体・目は同じ変形グループにあり、巻きと尾の根元は胴体の内側へ埋めて接合しています。尾の初回試作で露出していた根元の端面を、胴体内へ移動して修正しました。上下変形に回転の傾きを重ねると底面が下がるため、揺れを水平回転へ変更し、全頂点が接地用の最低高さを超えることを単体テストでも検証しています。明るい輪郭が部分的に細く見える箇所はありますが、裏面に抜ける接合穴は確認していません。

## 透明度の比較と採否

標準品質だけで `uAlpha=0.72`、透明描画・深度書き込みなしの[透明度試作](scene/transparent-prototype.png)を比較しました。巻き・尾の重なりが胴体越しに見えて部品の境界が強調されるため、採用していません。両品質とも体表は不透明で深度を書き込み、縁・階調・内部の淡い帯で透明感を出します。目も不透明、深度テスト有効で、常時最前面の描画は使いません。

## 再現と資源

`npm run dev` 後、`/src/scene/qa.html` を開くとモデルを直接確認できます。`?quality=low` で軽量形状を選択します。`PLAYWRIGHT_BROWSERS_PATH=/tmp/pw-browsers node src/scene/capture.mjs --video` で静止画・動画・代替画像を再生成できます（Playwright Chromium、動画用ffmpegが必要）。ブラウザコンソールの `window.sceneQA.setAngle(ラジアン)`、`setTime(秒)` で同じ画角と時刻を再現し、`animate(true)` で待機します。`transparency(true)` は比較試作専用でアプリから呼ばれません。`info()` は描画回数、三角形、メモリ資源数を返します。`public/slime-fallback.webp` はこの完成モデルを `setAngle(0.3)`, `setTime(0)` でWebP出力した静止代替です。

標準の単体QA（接地影込み）は11,800三角形・10描画、軽量は4,508三角形・10描画、法廷全体QAは静的形状の材質別結合後で15,878三角形・31描画でした（結合前15,842三角形・73描画）。参照JPEGと外部テクスチャをアプリ起動時に読み込みません。通常のピクセル比上限は標準1.5、軽量1.0。33.3msを超えるフレームが継続して45回分蓄積した場合は、実測に基づいてピクセル比を1へ下げます。短い停止だけでは下げず、速いフレームで蓄積を減らします。高密度画面またはCPUコア数の少ない環境は軽量を選びます。全画面の後処理や屈折・透過、シャドウマップは使いません。

静的な法廷は同じ材質の直下メッシュを結合し、各人物の親グループと姿勢を残しました。結合前の66描画要素が24以下になることをRED→GREENで検証しています。三角形数はほぼ同じですが、非インデックス化による頂点バッファ増加と、結合後の粗いカリングを引き換えにしています。スライムは結合せず、全ての中立変形を維持しています。

`mountScene` は画面外・非表示タブでRAFを停止し、復帰時のフレーム差分を最大50msに制限します。OSと画面の動きを減らす設定は固定ポーズ、`still` は描画を継続しません。WebGL作成失敗とcontext lostは一度だけ代替表示のコールバックを呼びます。`dispose()` はRAF、監視、イベント、形状、素材、階調テクスチャ、レンダラーを解放します。

## 検証環境と結果

Linuxの管理コンテナ、Playwright Chromium 156.0.8078.4（ANGLE SwiftShader）、720×800・ピクセル比1で単体を撮影しました。軽量の縮小確認は160×180です。iPhone/Safari実機ではありません。

- RED: 未実装で上限時間・2つの目・3人の人物の3検査が失敗。床の最低高さの追加検査も `0.01805 < 0.02` で失敗を確認後に修正。
- `npm test -- tests/unit/slime-animation.test.ts`: 11件PASS。dt=0、最大50ms、動きを減らす固定ポーズ、同時刻の再現、目の素材、床面、三角形予算、人物、継続的な遅延による解像度低下と一時的な遅延の区別、法廷の描画数24以下と人物グループ保持を検査。
- `PLAYWRIGHT_BROWSERS_PATH=/tmp/pw-browsers npx playwright test tests/e2e/scene.spec.ts --output=/tmp/slime-scene-results`: 2件PASS。WebGL不可でも静止代替から裁判を操作でき、context lostで同じ静止代替へ切り替わることを検査。
- `npx tsc --noEmit`: PASS。全体の `npm test`: 79件PASS（最終13:20:02 UTC）。

60秒×3回ずつの標準/軽量計測は [performance.json](scene/performance.json) に生データを保存しました。結合前の6回分は [performance-baseline.json](scene/performance-baseline.json) です。`SLIME_DISABLE_HMR=1 npm run dev` で安定したサーバーを起動後、`PLAYWRIGHT_BROWSERS_PATH=/tmp/pw-browsers node src/scene/performance.mjs` で同じ実時間計測を再実行できます。ソフトウェア描画のコンテナ計測なので、実機の30fps達成を示す値としては扱いません。iPhone Safari実機での速度・熱・バッテリーと長時間運用は公開前に別途確認する必要があります。


### 実時間60秒の6回計測（静的形状結合後）

390×320、DPR1、単体QAの法廷とスライム、同時に開発作業がある管理コンテナで測定。全て60,000ms以上のRAF間隔を直接収集しました。アプリ全体や実機の描画速度の保証には用いません。

| 品質 | 回 | 実測秒 | 平均fps | p95 ms | 描画 / 三角形 |
| --- | --- | --- | --- | --- | --- |
| standard | 1 | 60.052 | 35.55 | 66.7 | 31 / 15878 |
| standard | 2 | 60.001 | 41.63 | 50.0 | 31 / 15878 |
| standard | 3 | 60.005 | 41.18 | 50.0 | 31 / 15878 |
| low | 1 | 60.014 | 52.20 | 33.4 | 31 / 8586 |
| low | 2 | 60.011 | 52.37 | 33.4 | 31 / 8586 |
| low | 3 | 60.011 | 51.69 | 33.4 | 31 / 8586 |

この環境では結合後の軽量品質の平均は51.69〜52.37fpsでしたが、p95は33.4msで目安の33.3msをわずかに超えています。標準は35.55〜41.63fps・p95は50〜66.7msでした。したがって「対象端末で安定30fps・p95≤33.3ms」を達成済みとは報告しません。6回を通して各品質のGPU資源数は31形状・1テクスチャ・6プログラムで一定でした。結合前のp95は標準83.3〜100ms、軽量50〜66.7msでした。

最終レビュー後、実シーンのRAFを計測する回帰試験を追加しました。手動停止→OS設定の有効/無効→裁判→ホームの全てで待機RAFが0、350msの間に追加実行が0となることを確認しています（追加1件PASS）。停止中もcanvasと裁判の入力は表示されます。全体単体試験の最終件数は80件です。
