# Three.js・3Dアニメ風デザイン仕様

2026-10-23。添付デザインを3Dへ移すための制作方針。添付で確定した外見を除き、数値・素材構成・カメラは実装開始時の提案です。

[要件](../requirements.md) · [実装計画](../superpowers/plans/2026-10-23-slime-trial.md) · [参照画像](../references/slime/README.md)

## 画作り

中世風の石と木の法廷に、淡い青紫のスライムが一匹いる。丸みのある輪郭、整理された2〜3段階の陰影、大きな白いハイライトでアニメの一場面に寄せる。背景は彩度を抑えた温かい石色・木色とし、スライムの淡い色が埋もれない明度差をつける。文字は不透明なパネル上に置く。

3Dモデルを実際に異なる方向から描画する。添付JPEGを平面に貼っただけの表現は完成形にしない。画像は厳密な正投影図ではないため、奥行きや部位の接合には制作上の補完が必要になる。最初に正面・背面・左右側面・斜めの静止画を作り、同じキャラクターとして見えることを確認する。

## スライムの造形と素材

| 部位 | 添付から維持する特徴 | Three.jsでの制作方針 | 確認点 |
| --- | --- | --- | --- |
| 胴体 | 下部が広い丸いゼリー状の体。接地部は平らすぎず柔らかい | 単位高さ1の胴体を基準に、頂点を調整した閉じたBufferGeometry。球を置くだけで終えず、左右差と裾の流れを作る | 横・背面でも厚みがあり、変形中に床へ突き抜けない |
| 頭頂部 | 大きく曲がり、先端が内側へ巻く液体の渦 | 中心線と断面半径を持つ立体形状。根元を胴体へ滑らかにつなぐ | 正面・側面・背面で先端が板状にならない |
| 後方の流れ | 裾から後ろへ続く、波のような輪郭と小さな巻き込み | 胴体と接合する立体の裾・尾。揺れは小さく、重なりを必要最小限にする | 尾だけ別の生物や炎に見えない |
| 目 | 濃い藍色の縦長の楕円。下側に青い反射。口なし | 前面に沿わせた2枚の曲面。材質は不透明。胴体の変形に追従させる | 正面で2つ、側面で自然に片方が隠れ、背面には見えない |
| しずく | 周囲に浮く丸形・細長い液滴 | 基本3個、小さな独立メッシュを同じモデルの子要素にする | 一匹の体の一部としてのみ扱い、分裂・増殖の演出をしない |
| 体表 | 乳白色から薄い青紫の透明感、白い艶、青紫の縁 | 独自の軽量シェーダーで段階的な陰影、視線角に応じる縁の光、大きな艶を合成する | ガラスの写実表現より添付の絵柄を優先。輪郭が背景に溶けない |

最初の色案は体の基色 `#DCE6FF`、影 `#A8B8F4`、縁 `#9297F2`、目 `#403487`、艶 `#FFFFFF`。画像から厳密に採色した値ではなく調整開始値とする。実装者が明度とライトを変え、添付と並べた画像で調整理由を記録する。

### 透明感と描画順

初期品質は「透明感のあるアニメ塗り」とする。胴体は不透明の深度を書き込む素材を基本に、内部の淡い流れ模様と縁の光で半透明感を作る。これにより背面から目が透けたり、重なる部位が描画順で消えたりする問題を避ける。目は胴体表面よりわずかに前へ置き、深度テストを有効にする。全面の `depthTest=false` や常時最前面描画では解決しない。

実際に背景が透ける表現は標準品質の候補として比較試作する。採用する場合も単層の体表を基本とし、カメラ角度と体の変形を組み合わせて描画順を検証する。半透明の胴体を何重にも重ねない。軽量品質でも添付の淡い色・縁・艶を残す。

法廷と人物には `MeshToonMaterial` の階調テクスチャを用いる。Three.js公式資料では `gradientMap` にNearestFilterを指定する。物理透過の候補 `MeshPhysicalMaterial` は有効化する効果に応じて描画負荷が増えるため、全端末の必須条件にしない。[MeshToonMaterial](https://threejs.org/docs/pages/MeshToonMaterial.html)・[MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)

## 法廷・人物・カメラ

| 対象 | 初回公開の範囲 |
| --- | --- |
| 法廷 | 石造りの壁、木の机、裁判官席、検察席、弁護士席、スライムの台。共通の1シーンをホームと裁判で再利用 |
| 人物 | 裁判官・検察・弁護士の簡略化した3D人物。複雑な顔の表情や口の同期は不要。証言本文はHTMLで常に読める |
| 明かり | 主光源1つと環境光。柔らかい接地影。窓からの光は固定し、投票の符号で照明色を変えない |
| カメラ | 小さな遠近感を残す固定のPerspectiveCameraを初期案にする。縦横で構図を調整し、スライム全体と主要な法廷家具を収める |
| 裁判画面 | 上部に3D、下部に事実・両者の見解・回答。小画面では3Dを小さくでき、本文を読むためのスクロールを妨げない |
| 結果・最新状況 | チャートと小説を中心にする。3Dは静止または低頻度で、数値更新のたびに全シーンを作り直さない |

天使の輪、悪魔の角、羽、悪意を示す笑い、回答を褒める目の変化は加えない。公開処刑の実行場面は3D化しない。最大の厚遇もスライムの幸福を保証する演出にはしない。

## アニメーション

| 状態 | 動き | 制約 |
| --- | --- | --- |
| 待機 | 4〜6秒周期の小さな伸縮、渦・裾・しずくの遅れた揺れ | 呼吸や感情があると物語上断定しない |
| 入廷 | 一度だけ短い移動と柔らかい着地 | スキップ可能。入力を待たせない |
| 審理中 | 待機と同じ中立的な動き | 選んだ点数や検察・弁護士の切替をアニメーション入力に渡さない |
| 送信中 | スライムは中立のまま。処理状態は画面部品で示す | 送信成功を喜び、失敗を悲しみに対応させない |
| 動きを減らす設定 | 静止ポーズ | OSの `prefers-reduced-motion` を反映し、画面内の切替も用意 |
| 非表示・画面外 | 描画ループ停止 | 復帰時に経過時間を上限50msへ制限し、大きく跳ねない |

物理流体シミュレーションは使わず、頂点変形と部位の移動で作る。座標変形と法線の扱いをそろえ、胴体・目・渦の接合が離れないことを確認する。

## 初期性能予算と代替表示

以下は未計測の制作目標であり、達成済みの数値ではない。実装計画のT03・T09で測定して記録する。

| 項目 | 初期目標 |
| --- | --- |
| 表示速度 | 対象端末で安定30fps以上。負荷を含む60秒の測定を3回行い、95パーセンタイルのフレーム時間33.3ms以下を目安にする |
| ポリゴン | スライム20,000三角形以下、法廷全体80,000三角形以下 |
| 描画呼出し | 1フレーム100回以下を初期上限 |
| 解像度 | devicePixelRatioを標準1.5、軽量1.0までに制限。文字・図はDOM/SVGで鮮明さを保つ |
| 画像 | 3D用テクスチャは原則1024px以下。参照JPEG4枚はゲーム起動時に読み込まない |
| 影・後処理 | 接地影の簡略表示から開始。全画面ブルーム、多段の透過・屈折、画面全体の輪郭抽出を初期必須にしない |

低速時は解像度、影、実透過の順で落とす。WebGLが使えない場合は同じスライムの静止画に切り替え、裁判、送信、集計、画像保存を利用できる状態を維持する。静止画は制作した3Dモデルから書き出す予定で、この文書に完成素材が存在するという意味ではない。

## 見た目の受入確認

T03で単体モデルの5方向静止画と短い待機動画、T04でホームと裁判の縦横画面、T09で完成画面と保存画像を提出する。確認用の固定時刻・乱数シードを用意し、比較画像の条件をそろえる。

- 参照画像と並べ、胴体・渦・裾・目・しずくの5要素が確認できる。
- 360度回転と伸縮の最大・最小で、目の裏抜け、透明部の欠落、接合の穴、床への貫通がない。
- 3Dを止めても、事実・両者の見解・10選択肢を欠かさず操作できる。
- 端末名、OS、ブラウザ、画質、画面幅、測定方法を記録する。ブラウザの端末模擬をiPhone実機確認として報告しない。

最初の造形確認が終わってから法廷全体を磨く。作成者はPRに添付された静止画・動画と公開前のプレビューで確認でき、PC用モデリングソフトの操作を前提にしない。
